## DARK MODE
- localStorage key: "theme" (values: "light" | "dark")
- On page load: read localStorage → fallback to system prefers-color-scheme
- Apply data-theme="dark" on <html> BEFORE first paint
  → Inline <script> in <head> (prevents flash of wrong theme)
- Toggle button: top-right, sun/moon inline SVG icon, no label
- Toggle saves choice to localStorage and updates data-theme on <html>

Inline script template (place in BaseLayout <head> before any CSS):
```html
<script is:inline>
  const theme = localStorage.getItem('theme') ||
    (window.matchMedia('(prefers-color-scheme: dark)').matches ? 'dark' : 'light');
  document.documentElement.setAttribute('data-theme', theme);
</script>
```

## LANGUAGE
The frontmatter `language` field ('en' | 'it', default 'en') must actually be
consumed — it sets the document language for accessibility and SEO.

- BaseLayout.astro accepts a `lang` prop (string, default 'en') and renders
  `<html lang={lang} ...>`.
- Every page passes a value:
  - Article pages pass `entry.data.language`.
  - Static pages (home, /articles, /about, /now, /tag, /search, 404) pass 'en'
    (or omit, relying on the default).
- The inline theme script still sets data-theme on the same <html> element;
  lang and data-theme coexist.

## UTILITIES

### src/utils/readingTime.ts
```ts
export function getReadingTime(content: string): string {
  const words = content.trim().split(/\s+/).length
  const minutes = Math.ceil(words / 200)
  return `${minutes} min read`
}
```

### src/utils/formatDate.ts
Format: "June 3, 2025" (no weekday, no time)
```ts
export function formatDate(date: Date): string {
  return date.toLocaleDateString('en-US', {
    year: 'numeric', month: 'long', day: 'numeric', timeZone: 'UTC'
  })
}
```
IMPORTANT — timeZone: 'UTC' is required, not optional. YAML frontmatter dates
(e.g. `date: 2025-06-03`) are parsed by Astro as UTC midnight. Without
timeZone: 'UTC', toLocaleDateString uses the build/server local timezone, so
in any negative-offset timezone (e.g. the US) an article dated 2025-06-03
would render as "June 2, 2025". Forcing UTC makes the displayed day match the
frontmatter day everywhere, and makes the unit tests deterministic across CI
machines regardless of their TZ.
