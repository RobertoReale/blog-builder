## FEATURE 01 — SEO & Discoverability

The blog foundation is already built. Add the following SEO and
discoverability features to the existing codebase.
Do not change any existing functionality or design.

CRITICAL INSTRUCTION: Before writing any code, use your web search tools to:
1. Verify the current best practices for RSS feeds, JSON-LD structured data, sitemaps, and canonical URLs in Astro 4 — both the official Astro docs and community patterns.
2. Check the current versions and API of `satori` and `@resvg/resvg-js` — both packages evolve independently and their APIs change between major versions.
3. Read the heading font name from CLAUDE.md's STACK section ("Fonts:" line). This is the font to use in the OG image — not necessarily Lora. Convert the name to an @fontsource package (e.g. "Playfair Display" → @fontsource/playfair-display). Then verify the correct internal file path for the 400-weight .woff file inside that package (the path layout `files/<name>-latin-400-normal.woff` is common but changes between major @fontsource versions — check the actual package contents). If the font is Lora, the example path is `node_modules/@fontsource/lora/files/lora-latin-400-normal.woff` — verify this still exists.
4. Verify that `satori` + `@resvg/resvg-js` is still the recommended approach for OG image generation in Astro static sites — if a built-in Astro feature or a more actively maintained package has emerged, add a `<!-- ALTERNATIVE: <name> — <reason> -->` comment in the OG image generation file, but implement what is specified here.
If you encounter a bug you cannot resolve by reading the code, search online for known issues and solutions before giving up.

### 1. RSS feed at /rss.xml

Install @astrojs/rss.
Create src/pages/rss.xml.ts.

Feed content:
- Title: SITE.title
- Description: SITE.description
- Site: SITE.url
- Items: all published articles, sorted by date descending
- Each item: title, description, pubDate (from frontmatter date),
  link (/article/[slug]), and full content if possible

---

### 2. sitemap.xml

Install @astrojs/sitemap.
Add to astro.config.mjs integrations.
Configure with SITE.url as the base.

Include in sitemap:
- / (homepage)
- /articles
- /about
- /now
- /article/[slug] for all published articles
- /tag/[tag] for all tags

Exclude: drafts, /rss.xml

---

### 3. robots.txt

Create src/pages/robots.txt.ts (dynamic, so SITE.url is used correctly):

```ts
import type { APIRoute } from 'astro'
import { SITE } from '../config'

export const GET: APIRoute = () => {
  return new Response(
    `User-agent: *\nAllow: /\nSitemap: ${SITE.url}/sitemap-index.xml\n`,
    { headers: { 'Content-Type': 'text/plain' } }
  )
}
```

This generates /robots.txt at build time with the correct site URL from config.ts.
Do NOT create a static public/robots.txt — it would hard-code the wrong URL.

---

### 4. Canonical URL

In BaseLayout.astro <head>, add:
```html
<link rel="canonical" href={canonicalURL} />
```

BaseLayout should accept a `canonicalURL` prop (string).
Each page constructs its canonical URL as: `${SITE.url}${Astro.url.pathname}`
Pass it to BaseLayout from every page.

---

### 5. 404 page

Create src/pages/404.astro.

Design:
- Use BaseLayout
- Centered content (same max-width as rest of site)
- Large "404" in Lora, muted color
- Short message: "This page doesn't exist."
- Link back to homepage: "← Back to home"
- No other content, no suggestions, no search

### 6. JSON-LD structured data (Article pages only)

In ArticleLayout.astro or src/pages/article/[slug].astro, add to <head>:

```html
<script type="application/ld+json" set:html={JSON.stringify({
  "@context": "https://schema.org",
  "@type": "BlogPosting",
  "headline": title,
  "description": description,
  "datePublished": date.toISOString(),
  "author": {
    "@type": "Person",
    "name": SITE.author
  },
  "url": `${SITE.url}/article/${slug}`,
  "publisher": {
    "@type": "Person",
    "name": SITE.author
  }
})} />
```

If coverImage is present, add "image" field with full URL.
Only render on article pages, nowhere else.

### 7. Open Graph images

Generate a static 1200×630 PNG for every article at build time so that social
links (X, LinkedIn, WhatsApp, iMessage) show a proper preview card.

Install the required packages:
```
npm install satori @resvg/resvg-js
```

Create src/pages/og/[slug].png.ts:
```ts
import type { APIRoute, GetStaticPaths } from 'astro';
import { getCollection } from 'astro:content';
import satori from 'satori';
import { Resvg } from '@resvg/resvg-js';
import { readFile } from 'node:fs/promises';
import { SITE } from '../../config';

export const getStaticPaths: GetStaticPaths = async () => {
  const articles = await getCollection('articles', (e) => e.data.status === 'published');
  return articles.map((a) => ({
    params: { slug: a.slug },
    props: { title: a.data.title, description: a.data.description },
  }));
};

export const GET: APIRoute = async ({ props }) => {
  const { title, description } = props as { title: string; description: string };

  // Read the heading font and colors from CLAUDE.md before writing this file:
  // - HEADING_FONT: the font name from CLAUDE.md STACK section (e.g. 'Lora', 'Playfair Display')
  // - FONT_PACKAGE: @fontsource package name (e.g. 'lora', 'playfair-display')
  // - FONT_FILE: the .woff file path inside the package (e.g. 'lora-latin-400-normal.woff')
  // - DARK_BG, DARK_TEXT, DARK_MUTED: hex values from CLAUDE.md dark mode palette
  const fontPath = new URL(
    '../../../node_modules/@fontsource/FONT_PACKAGE/files/FONT_FILE',
    import.meta.url,
  );
  const fontData = await readFile(fontPath);

  const svg = await satori(
    {
      type: 'div',
      props: {
        style: {
          width: '100%',
          height: '100%',
          display: 'flex',
          flexDirection: 'column',
          justifyContent: 'flex-end',
          padding: '60px',
          backgroundColor: 'DARK_BG',
          color: 'DARK_TEXT',
          fontFamily: 'HEADING_FONT',
        },
        children: [
          {
            type: 'p',
            props: {
              style: { fontSize: '15px', color: 'DARK_MUTED', marginBottom: '24px' },
              children: SITE.author,
            },
          },
          {
            type: 'h1',
            props: {
              style: { fontSize: '48px', lineHeight: 1.2, margin: '0 0 20px' },
              children: title,
            },
          },
          {
            type: 'p',
            props: {
              style: { fontSize: '20px', color: 'DARK_MUTED', margin: 0 },
              children: description,
            },
          },
        ],
      },
    },
    {
      width: 1200,
      height: 630,
      fonts: [{ name: 'HEADING_FONT', data: fontData, weight: 400, style: 'normal' }],
    },
  );

  const resvg = new Resvg(svg, { fitTo: { mode: 'width', value: 1200 } });
  const pngBuffer = resvg.render().asPng();

  return new Response(pngBuffer, {
    headers: {
      'Content-Type': 'image/png',
      'Cache-Control': 'public, max-age=31536000, immutable',
    },
  });
};
```

IMPORTANT: Replace ALL placeholders above before writing the final file:
- DARK_BG     → `--color-bg` dark mode hex from CLAUDE.md
- DARK_TEXT   → `--color-text` dark mode hex from CLAUDE.md
- DARK_MUTED  → `--color-muted` dark mode hex from CLAUDE.md
- HEADING_FONT → heading font display name from CLAUDE.md (e.g. `Lora`)
- FONT_PACKAGE → @fontsource package name (e.g. `lora`, `playfair-display`)
- FONT_FILE   → verified .woff filename inside the package (CRITICAL INSTRUCTION item 3)
Satori runs at build time and cannot read CSS custom properties, so hardcoded hex is
required here. Read the values from CLAUDE.md and use them directly. Remove the
inline comments (// replace with...) from the written file.

After creating the endpoint, update the article head meta tags.
In src/pages/article/[slug].astro (or wherever the article OG tags live):

- Replace any conditional `og:image` (previously only set when coverImage existed)
  with an unconditional reference to the generated image:
  ```html
  <meta property="og:image" content={`${SITE.url}/og/${slug}.png`} />
  <meta property="og:image:width" content="1200" />
  <meta property="og:image:height" content="630" />
  ```
- Update `twitter:card` to always be `summary_large_image` (every article now has a generated image):
  ```html
  <meta name="twitter:card" content="summary_large_image" />
  ```
