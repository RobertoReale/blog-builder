### 1. SeriesNav component

Create src/components/ui/SeriesNav.astro

Props:
```ts
{
  series: string          // series name (display)
  seriesSlug: string      // URL-safe version (lowercase, hyphens)
  currentPart: number

    part: number
```

UI design:

- Subtitle: "Part {currentPart} of {totalParts}"
  Lora, slightly larger than body, var(--color-text)

  Two small links below the list (if prev/next exist):
  "← Part N: Title" and "Part N: Title →"
  DM Sans, 14px, var(--color-muted) → var(--color-text) on hover
- Outer wrapper: border-left 3px solid var(--color-border), padding 16px 20px
- Background: none (keep it clean)

Position in article layout:
SeriesNav renders immediately after the article header (title, date, reading
time, tags) and before everything else in the body region.

Canonical order of elements after the header (so Features 02 and 04 don't
fight over the same slot):
  1. SeriesNav            (this feature, if the article is in a series)
  2. Origin block         (only if originPosition === 'top')
  3. TOC                  (Feature 02, if 3+ QA blocks)
  4. Article body (MDX)
The "before the Origin block regardless of originPosition" rule only concerns a
top Origin; a bottom Origin stays at the bottom near Sources, untouched.

### 5. URL-safe series slug utility

Create or add to src/utils/slugify.ts:
```ts
export function slugify(str: string): string {
  return str
    .toLowerCase()
    .trim()
    .replace(/[^\w\s-]/g, '')   // remove special chars
    .replace(/[\s_]+/g, '-')    // spaces AND underscores → hyphens
    .replace(/-+/g, '-')        // collapse consecutive hyphens
}
```

Use this everywhere series names are used in URLs.
