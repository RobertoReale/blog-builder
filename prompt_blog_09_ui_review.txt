## FINAL STEP — UI, UX & Design Quality Review

All features are built and E2E-tested. This is the final quality gate.
Read CLAUDE.md first — it is the authoritative source for the design system.

Your goal: audit every page and component for visual consistency,
accessibility, and UX polish. Fix every issue you find.
Do not add new features — only fix what is already there.

CRITICAL INSTRUCTION: Before fixing anything, use your web search tools to
look up current Astro accessibility patterns, WCAG 2.1 AA requirements for
personal blogs, and any known dark-mode or CSS variable pitfalls in Astro 4.
If you encounter a bug you cannot resolve from the code alone, search online
before giving up.

### 1. Design System Consistency

Grep all .astro, .css, and .ts files for raw hex color values:

  Pattern: #[0-9a-fA-F]{3,6}\b

The ONLY file allowed to contain hex values is src/styles/global.css.
Every hex found elsewhere must be replaced with the appropriate CSS variable:

  --color-bg       → page background
  --color-surface  → card/callout/code-block background
  --color-text     → primary text
  --color-muted    → secondary text, dates, metadata, captions
  --color-accent   → links, active states, focus rings, progress bar
  --color-border   → dividers, card outlines, TOC left border

Fix every violation you find.

### 3. Dark Mode Completeness

Verify the FOUC-prevention script is present in src/layouts/BaseLayout.astro
inside the <head>, before any stylesheets:

```html
<script is:inline>
  const theme = localStorage.getItem('theme') ||
    (window.matchMedia('(prefers-color-scheme: dark)').matches ? 'dark' : 'light');
  document.documentElement.setAttribute('data-theme', theme);
</script>
```

If missing, add it.

Check src/styles/global.css:
- A [data-theme="dark"] block exists with all six color variables redefined
- No color value appears in only one theme (light/dark must both define every
  interactive state — hover, active, focus)

Check every component for hardcoded colors that would not adapt to dark mode
(see Section 1 above). Dark mode fails silently — text can become invisible
(e.g., color: black on a dark background) and the only way to catch it is to
read the source.

### 4. Accessibility (WCAG 2.1 AA)

Audit every component file in src/components/:

**Images:**
- Every <img> tag must have a non-empty alt attribute
- Decorative images (purely visual, no information) should use alt=""
- The ImageWithCaption.astro component must pass alt through to <img>

**Icon-only buttons:**
- ThemeToggle.astro: aria-label="Toggle dark mode"
- BackToTop.astro: aria-label="Back to top" (or equivalent)
- ShareButton / share button in the article header: aria-label or visible text

**Links:**
- Navigation links must have descriptive text (not bare URLs or icons without labels)
- "Read more" links (if any) must include the article title for context:
  e.g., aria-label="Read more: Article Title"

**Focus styles:**
- Search src/styles/global.css for `outline: none` or `outline: 0`
- If found and not replaced with a custom focus ring, add one:
  ```css
  :focus-visible {
    outline: 2px solid var(--color-accent);
    outline-offset: 2px;
  }
  ```

**Semantic HTML:**
- BaseLayout.astro must use <header>, <main>, <footer> as landmarks
- Article pages must wrap the article body in <article>
- Navigation must be in a <nav> element

**Heading hierarchy (check each page template):**
- Each page renders exactly one <h1>
- Heading levels are never skipped (h1 → h2 → h3, never h1 → h3)
- The article title in ArticleLayout.astro is an <h1>
- TOC links reference h2/h3 headings — verify no h4/h5/h6 headings are missed
  (this is acceptable; TOC only needs h2/h3)

**Search input:**
- src/pages/search.astro: the search input has an aria-label or an associated <label>

Fix every accessibility issue found.

### 5. Responsive Design

Check the following in each layout and component:

**Article page:**
- TOC (src/components/ui/TOC.astro) uses a <details>/<summary> element on mobile
  so it collapses. On desktop it should always be expanded (CSS media query or
  the details element is left open by default).
- Article body max-width (680px) has horizontal padding on small screens
  so text doesn't touch screen edges (e.g., padding: 0 1rem on mobile)

**Navigation (BaseLayout.astro):**
- Nav links do not overflow on narrow screens
- Logo/title is not truncated

**BackToTop button:**
- Must be at least 40×40px (adequate touch target on mobile)
- Must not overlap the article text on mobile (positioned far enough right/bottom)

**General:**
- No element has a fixed width wider than 100vw
- Images inside articles are max-width: 100%

Fix any responsive issues found.
