Pagefind runs entirely at build time — no server required.

### 1. Install and configure Pagefind

Install: `npm install pagefind`

Update package.json scripts:
```json
"build": "astro build && pagefind --site dist",
"build:astro": "astro build",
"build:index": "pagefind --site dist",
"preview": "astro preview"
```

The pagefind command runs after the Astro build and indexes the dist/ folder.
Note: on Windows, `&&` in npm scripts can be unreliable. If `npm run build` fails,
run the two steps separately: `npm run build:astro` then `npm run build:index`.

---

### 2. Mark content for indexing

In ArticleLayout.astro (or the article page template):

Add `data-pagefind-body` to the main article content wrapper.
This tells Pagefind to index only the article body, not nav/footer.

```html
<article data-pagefind-body>
  <!-- article content here -->
</article>
```

Add `data-pagefind-ignore` to elements that should NOT be indexed:
- <nav>
- <footer>
- TOC (Table of Contents, if present)
- Sources section
- Tag pills

Add metadata for better search results (in the article head or near body):
```html
<div data-pagefind-meta="title">{title}</div>
<div data-pagefind-meta="description">{description}</div>
<div data-pagefind-meta="date">{formattedDate}</div>
```
These can be visually hidden if needed (but don't use display:none — 
use a visually-hidden CSS class instead).

### 3. Search page

Create src/pages/search.astro

Layout: use BaseLayout, same max-width as rest of site.

UI:
- H1: "Search" (heading font — inherited from global.css, same as all other h1s)
- Search input: full width of content column, DM Sans, 18px,
  border: 1px solid var(--color-border), padding 12px 16px,
  no border-radius (or very subtle 4px), background var(--color-bg),
  color var(--color-text).
  Add the `autofocus` attribute so the cursor lands in the field on page load —
  this is what makes the "/" shortcut below feel instant (it navigates here,
  and the page focuses the input itself).
- Results appear below the input as the user types (no submit button)
- Each result: same style as ArticleCard (title + description + date)
  but populated from Pagefind result data
- If no results: "No results for '[query]'" in muted text
- While loading: "Searching..." in muted text

Pagefind UI integration:
Use Pagefind's JS API (not the default UI widget) to keep full design control:

```html
<script>
  async function initSearch() {
    const input = document.getElementById('search-input')
    const results = document.getElementById('search-results')
    if (!input || !results) return
    
    let pagefind
    try {
      // Pagefind only exists in the production build (astro build && pagefind).
      // In `npm run dev` this import 404s, so guard it instead of crashing.
      pagefind = await import('/pagefind/pagefind.js')
      await pagefind.init()
    } catch {
      results.innerHTML = '<p class="muted">Search is available in the built site (run npm run build && npm run preview).</p>'
      return
    }

    // Remove existing listener to prevent duplicates across navigations if using is:inline,
    // or simply add the listener. (Astro module scripts run once, but astro:page-load fires multiple times)
    input.addEventListener('input', async (e) => {
      const query = e.target.value.trim()
      if (!query) { results.innerHTML = ''; return }
      const search = await pagefind.search(query)
      const data = await Promise.all(search.results.slice(0, 10).map(r => r.data()))
      renderResults(data, results)
    })
  }
  
  document.addEventListener('astro:page-load', initSearch)
  
  function renderResults(items, container) {
    container.innerHTML = ''
    if (!items.length) {
      const msg = document.createElement('p')
      msg.className = 'muted'
      msg.textContent = 'No results.'
      container.appendChild(msg)
      return
    }
    for (const item of items) {
      const a = document.createElement('a')
      a.href = item.url           // URL comes from Pagefind's own built index
      a.className = 'search-result'

      const h2 = document.createElement('h2')
      h2.textContent = item.meta?.title || 'Untitled'

      const p = document.createElement('p')
      p.textContent = item.meta?.description || item.excerpt || ''

      const span = document.createElement('span')
      span.className = 'muted'
      span.textContent = item.meta?.date || ''

      a.append(h2, p, span)
      container.appendChild(a)
    }
  }
</script>
```

Style .search-result to match ArticleCard (no border, just spacing,
title in the heading font linking to the article, description in muted DM Sans).

### 5. Keyboard shortcut (optional but recommended)

When user presses "/" anywhere on the site (not while typing in a field),
navigate to /search. The input is focused by the search page's `autofocus`
attribute (see section 3), so no extra focus logic is needed after navigation.

```js
document.addEventListener('keydown', (e) => {
  const el = document.activeElement
  const typing = el && (
    el.tagName === 'INPUT' ||
    el.tagName === 'TEXTAREA' ||
    el.isContentEditable
  )
  if (e.key === '/' && !typing) {
    e.preventDefault()
    window.location.href = '/search'
  }
})
```

Add to BaseLayout so it works site-wide.
